# HKCardVault - 角色權限存取控制 (RBAC) 介面設計與功能拆解筆記

本筆記詳細記錄 **HKCardVault** 平台在登入後的 Role-Based Access Control (RBAC) 權限劃分與各角色的專屬介面（Sub-tabs）設計。平台採用唯一色彩模式——**暗金色深色主題 (Dark Mode Only)**，確保所有介面在符合視覺美學的前提下，提供高效率、高精確度的數據展示與操作。

---

## 1. 一般會員 (USER)
一般會員的介面以**「消費、探索、收藏」**為核心。在行動裝置（Mobile）上，主要透過底部置中的**「浮動液體玻璃選項卡欄 (Floating Liquid Glass Bottom Nav)」**進行核心功能的流暢導航。

| 導航/子分頁 (Sub-tab) | 專屬功能介面與 UI 細節 | 核心業務與數據交互 |
| :--- | :--- | :--- |
| 🏠 **首頁 (Home)** | • 實時成交牆 (Market Heat Marquee)<br>• 焦點市場推薦<br>• 每日簽到獎勵入口 | 滾動顯示全平台最新成交資訊；連續簽到達成里程碑（如 7 日）可獲得積分或運費抵用券。 |
| 🔍 **市場/搜尋 (Market)** | • 卡牌精準搜尋<br>• 歷史價格走勢圖（線圖）<br>• 股票式交易撮合面板 | 輸入卡牌編號自動帶出官方數據與高清原圖；結合 Mercari JP 真實已成交記錄展示價值升跌；支援最低價即時成交（直接購買）與掛單收購（即時出價）。 |
| 🎁 **收藏庫 (Collection)** | • 私人收藏管理介面<br>• 總身家自動計算器<br>• 身份等級徽章（如：資深收藏家） | 記錄用戶持有的卡牌，透過市價 API 自動計算整套收藏的總資產價值。根據成交量及好評率動態賦予稱號。 |
| 📦 **交易紀錄 (Orders)** | • 買家訂單追蹤列表<br>• 第三方鑑定託管進度條<br>• 自動交易提醒與催付通知 | 顯示購買歷史。高價值項目採用水平時間線步進器（步進狀態：`優惠 → 保管中 → 已發貨 → 檢查中 → 已釋放`），直觀追蹤 Escrow 資金鎖定與鑑定進度。 |
| 👤 **設定/帳戶 (Profile)** | • 個人資料修改面板<br>• 安全認證設定<br>• **「申請成為商戶 (KYC)」入口** | 允許一般用戶填寫店名並上載基本 KYC 證明文件。提交後用戶狀態變更為 `PENDING_MERCHANT`，等待管理員審核。 |

## 2. 商戶 (MERCHANT)
商戶（已通過 KYC 審核的商業或私人賣家）會保留一般會員的消費與探索功能，但在介面上會動態解鎖一個偏向專業金融工具佈局的**「賣方儀表板 (Seller Dashboard)」**。

| 導航/子分頁 (Sub-tab) | 專屬功能介面與 UI 細節 | 核心業務與數據交互 |
| :--- | :--- | :--- |
| 📊 **商戶總覽 (Dashboard)** | • 銷售統計圖表（溫暖金色數列）<br>• 當日營收與庫存中繼資料卡牌<br>• 待處理爭議或訂單提醒 | 提供商業賣家專屬的管理面板，以極簡、高清晰度的邊框圖表展示銷售趨勢，減少視覺競爭。 |
| 🗂️ **商品管理 (Inventory)** | • 庫存列表與即時狀態調整<br>• **自動化上架表單 (Listing Form)**<br>• 實物狀態相冊（強制 4-6 張） | 整合卡牌搜尋組件，輸入編號自動帶出官方名稱。強制賣家必須上傳 4-6 張高清實物照片（展示卡角、刮痕細節），確保品相透明。 |
| 🤝 **銷售訂單 (Sales)** | • 賣方訂單處理面板<br>• 物流單號 (Tracker) 填寫表單<br>• 內置聊天系統（附敏感資訊警告） | 當買家支付 10-20% 訂金啟動鑑定或全額付款後，提示商戶進行發貨。商戶自行安排寄件後在此上載物流證明與速遞單號。 |
| 💰 **資金與金流 (Finance)** | • Stripe Connect 帳戶綁定狀態<br>• 平台自動扣佣與分賬明細<br>• 定額運費補貼記錄 | 檢查是否已完成 Stripe Express 帳戶綁定（未綁定時顯示顯眼的 CTA 提示）。檢視免運費券或優惠由平台佣金中扣除並補貼給賣家的流水。 |

## 3. 管理員 (ADMIN)
管理員完全脫離前端的消費與交易介面，採用**桌面端（Desktop）為主**的後台管理佈局（`/admin` 路由），受到嚴格的 Middleware 攔截與 RLS 權限保護。介面強調高數據密度與全局管控效率。

| 導航/子分頁 (Sub-tab) | 專屬功能介面與 UI 細節 | 核心業務與數據交互 |
| :--- | :--- | :--- |
| 📈 **平台監控 (Overview)** | • 全局總成交額 (GMV) 監控<br>• Stripe 佣金收入總計<br>• 在線用戶與即時交易流速 | 實時監控平台整體運作與財務數據，作為營運決策與伺服器效能監控的核心看板。 |
| 🪪 **審核中心 (Approvals)** | • **商戶 KYC 申請審核面板**<br>• 證明文件高清查看器<br>• Approve / Reject 一鍵操作 | 列出所有 `PENDING_MERCHANT` 的申請件。管理員審核店名與 KYC 文件後，點擊 Approve 即可透過 Server Action 將用戶角色升級為 `MERCHANT`。 |
| 👥 **用戶管理 (Users)** | • 全局用戶名冊與雙向評分檢視<br>• 違規用戶停權控鍵 (Ban)<br>• 爭議訂單仲裁介入介面 | 建立高信任買賣環境。可封鎖違規用戶（標記 `is_banned = true`），並介入處理買賣雙方在鑑定、退款或物流上的爭議。 |
| 🗃️ **卡牌資料庫 (Database)** | • 新卡牌條目審核與上架<br>• 非 API 覆蓋小眾卡種手動錄入表單<br>• 外部數據快取更新控制器 | 審核用戶或系統自動抓取的卡牌條目；針對 TCGdex/JustTCG 未覆蓋之稀有或特殊卡牌，提供管理員手動維護與更新機制。 |
| ⚙️ **營運設定 (Settings)** | • 定額運費補貼金額靈活設定<br>• 數據爬蟲 (SKUNK/Mercari) 頻率微調<br>• Proxy 與匯率 API 授權管理 | 管理員可隨時根據市場策略與營運成本，彈性調整運費補貼金額，或手動觸發熱門卡牌（Top 100）的價格爬蟲更新。 |

## 4. 前端佈局與動態路由切換策略 (Layout Strategy)

1. **角色偵測與選單擴充**
   * 當系統偵測到用戶成功登入且 `role === 'MERCHANT'` 時，前端主要導航佈局（如行動端浮動選項卡欄或桌面端頂部導航）將會動態注入一個專屬的公事包/圖表圖示 (💼)，無縫導向 `/merchant/dashboard`。
   * 一般消費介面與商戶管理介面共用相同的**暗金色深色主題**，確保品牌視覺的一致性與尊貴感。

2. **管理員獨立隔離 (`/admin`)**
   * 管理員路由完全獨立於消費端 App Shell。Middleware 會強制驗證 `role === 'ADMIN'`，未授權者將直接重導向回主頁或 404。
   * 後台介面設計捨棄消費端的流體玻璃、卡牌懸停等娛樂化/遊戲化視覺，改用高密度邊框表格（Bordered Tables）、清晰的側邊導航欄（Sidebar Navigation），全面提升後台數據的掃描性與管理員的批次處理效率。

3. **狀態與安全性 (RLS) 雙重保障**
   * UI 層面的權限控制（如隱藏或顯示按鈕）僅為了提升使用者體驗；底層的 Supabase Database 與 Storage 均已配置嚴格的 Row Level Security (RLS) 規則。
   * 例如：只有 `role = MERCHANT` 的請求才能成功 INSERT 紀錄落 `listings` 表格或上載圖片至 `listing-images` 儲存桶。
